# Шаблон городских страниц услуг

Кластер: 1 главная → 3 хаба услуг → 12 городских страниц → блог.

```
templates/home.template.html                  главная         /
templates/service-hub.template.html           хаб услуги      /услуга/
templates/service-city.template.html          город           /услуга/город/
templates/blog-index.template.html            список статей   /blog/
templates/blog-post.template.html             статья блога    /blog/слаг/
templates/spasibo.template.html               благодарность   /spasibo/
templates/politika.template.html              политика        /politika/
templates/404.template.html                   не найдено      /404.html
templates/robots.txt                          robots          /robots.txt
templates/sitemap.xml                         карта сайта     /sitemap.xml
tools/build-sitemap.py                        генератор карты
examples/home.html                            пример: главная
examples/remont-holodilnikov-hub.html         пример: хаб холодильников
examples/remont-holodilnikov-surgut.html      пример: холодильники × Сургут
```

Все страницы и серверная обвязка собраны.

## robots / sitemap / 404 — три частые ошибки

1. **`Disallow: /spasibo/` в robots.txt.** robots управляет обходом, а не
   индексацией. Закрытая от обхода страница всё равно попадёт в выдачу, только
   без описания — и робот не прочитает её `noindex`. `/spasibo/` должна быть
   открыта для обхода и закрыта мета-тегом.
2. **`/spasibo/` в sitemap.xml.** Прямое противоречие с её `noindex`.
   Карту проще не править руками: `python3 tools/build-sitemap.py --site
   https://example.ru > sitemap.xml` (27 адресов, `/spasibo/` и 404 исключены).
3. **404 отдаёт 200 OK.** Сам HTML статус не задаёт — нужен `ErrorDocument 404
   /404.html` в Apache или `error_page 404 /404.html;` в nginx. Проверка:
   `curl -I https://example.ru/нет-такой-страницы/`. Редирект 301 с 404 на
   главную делает только хуже.

## Разделение уровней

Три уровня не должны конкурировать за одни запросы.

| | Главная `/` | Хаб `/услуга/` | Город `/услуга/город/` |
|---|---|---|---|
| Запросы | бренд, «ремонт техники на дому» | по услуге без гео | по услуге с гео |
| Задача | развести по услугам и городам | выбрать город, дать экспертизу | оставить заявку |
| Услуга в H1 | **нет** | да | да |
| Город в H1 | **нет** | **нет** | да |
| Прайс | «от N ₽» в офферах | ориентировочный | точный по городу |
| Уникальные блоки | 3 оффера, матрица городов, связанные селекты в формах | симптом→причина→цена, 6 поломок, гарантия, ремонт-или-замена | районы, карта, местные отзывы, городские вопросы |

Главная обязана отдавать ссылку каждой из 16 страниц кластера: 3 хаба, 12 городов, блог.

## Как получить страницу

Заменить токены `{{...}}` поиском-заменой. Полная легенда со значениями —
в комментарии в начале `templates/service-city.template.html`.

## Матрица город × услуга

Списки городов **разные** — следите за битыми ссылками.

| Услуга | Сургут | Нижневартовск | Нефтеюганск | Ханты-Мансийск | Нягань |
|---|:--:|:--:|:--:|:--:|:--:|
| `remont-stiralnyh-mashin` | ✓ | ✓ | ✓ | — | ✓ |
| `remont-holodilnikov` | ✓ | ✓ | ✓ | ✓ | — |
| `kompyuternaya-pomosch` | ✓ | ✓ | ✓ | ✓ | — |

Места, где список зашит:

- **город** — переключатель в topbar, блок «Услуга в других городах», подвал
- **хаб** — переключатель в topbar, секция `#cities`, три `<select>` в формах,
  JSON-LD (`areaServed` + `ItemList`), ссылки под прайсом, подвал
- **главная** — списки городов в карточках офферов, секция `#cities`,
  объект `SERVICE_CITIES` в скрипте внизу файла, JSON-LD `areaServed`, подвал

Матрица не прямоугольная: в Нягани только стиральные машины, в Ханты-Мансийске
их нет. Не дописывайте ссылки «для симметрии» — это 404.

## Что обязано различаться на каждой из 12 страниц

Иначе Яндекс склеит их как малоценные дубли.

1. Районы и посёлки выезда (`#local`)
2. Абзац про специфику города (`#local`)
3. Карта зоны выезда (`#local`)
4. 6 отзывов — имена, районы, модели техники (`#reviews`)
5. Цены — разводить хотя бы на ±10% (`#prices`)
6. 2 городских вопроса (`#faq`)
7. Статьи блога — строго по теме услуги (`#articles`)

## Ручные заглушки

Ищите в файле слово `ЗАГЛУШКА` — 14 ссылок `href="#"` и ~10 блоков контента.

## Кольцо перелинковки

```
городская ──→ статья ──→ хаб + все города услуги
    ↑                            │
    └────────────────────────────┘
```

Городская страница ссылается на статьи из блока «Когда пора вызывать мастера»,
хаб — из таблицы симптомов, статья возвращает ссылки на хаб и на все города
своей услуги (блок `#post-cities` и боковая колонка). Без обратных ссылок
статья собирает трафик и никуда его не отдаёт.

## /spasibo/

Все формы сайта редиректят сюда через `_next`. Три правила:

1. Цель в Метрике: «Посещение страниц», условие — URL содержит `/spasibo/`.
   Это основная конверсия сайта.
2. **Не** закрывать страницу в `robots.txt`. Иначе робот не прочитает
   `noindex` и страница всё равно попадёт в выдачу, только без описания.
3. Исключить из `sitemap.xml`. Формы на страницу не ставить.

## ⚠️ Formspree и 152-ФЗ

Все формы сейчас отправляют персональные данные в Formspree — сервис с
серверами в США. Это создаёт три расхождения с российским законом:

1. **Локализация баз данных** (ч. 5 ст. 18 152-ФЗ) — запись и хранение ПДн
   россиян должны производиться на серверах в РФ.
2. **Трансграничная передача** (ст. 12) — требует отдельного уведомления
   Роскомнадзора до начала передачи.
3. **Уведомление РКН об обработке ПДн** — подаётся всеми, кто собирает ПДн
   через формы.

Пока обработчик не сменён, раздел 8 политики честно описывает трансграничную
передачу (вариант А). После перехода на российский обработчик — замените его
на вариант Б из комментария в файле.

Варианты замены: свой `send.php` на хостинге в РФ, Яндекс Формы, Битрикс24,
amoCRM. Подробности — в комментарии в начале `politika.template.html`.

## Общий CSS и JS

Блоки `<style>` и `<script>` в обоих шаблонах совпадают (у хаба плюс несколько
своих классов в конце CSS). Пока страниц две — проще держать их встроенными.
Когда соберёте все 13, вынесите в `/assets/style.css` и `/assets/app.js`
и подключите `<link>` / `<script src>` — один файл вместо тринадцати копий
плюс кэш браузера.

## Правило синхронизации

Тексты FAQ продублированы в JSON-LD `FAQPage` в `<head>`. Правите вопрос
на странице — правьте и разметку, иначе это несоответствие разметки контенту.
То же с ценами: `{{PRICE_FROM}}` должен совпадать с минимумом в прайсе,
а `hasOfferCatalog` — с таблицей цен.
