## robots / sitemap / 404 — три частые ошибки

1. **`Disallow: /spasibo/` в robots.txt.** robots управляет обходом, а не
   индексацией. Закрытая от обхода страница всё равно попадёт в выдачу, только
   без описания — и робот не прочитает её `noindex`. `/spasibo/` должна быть
   открыта для обхода и закрыта мета-тегом.
2. **`/spasibo/` в sitemap.xml.** Прямое противоречие с её `noindex`.
   Карту проще не править руками: `python3 tools/build-sitemap.py --site
   https://example.ru > sitemap.xml` (27 адресов, `/spasibo/` и 404 исключены).
3. **404 отдаёт 200 OK.** Сам HTML статус не задаёт — нужен `ErrorDocument 404
   /404.html` в Apache или `error_page 404 /404.html;` в nginx. Проверка:
   `curl -I https://example.ru/нет-такой-страницы/`. Редирект 301 с 404 на
   главную делает только хуже.

## Разделение уровней

Три уровня не должны конкурировать за одни запросы.

| | Главная `/` | Хаб `/услуга/` | Город `/услуга/город/` |
|---|---|---|---|
| Запросы | бренд, «ремонт техники на дому» | по услуге без гео | по услуге с гео |
| Задача | развести по услугам и городам | выбрать город, дать экспертизу | оставить заявку |
| Услуга в H1 | **нет** | да | да |
| Город в H1 | **нет** | **нет** | да |
| Прайс | «от N ₽» в офферах | ориентировочный | точный по городу |
| Уникальные блоки | 3 оффера, матрица городов, связанные селекты в формах | симптом→причина→цена, 6 поломок, гарантия, ремонт-или-замена | районы, карта, местные отзывы, городские вопросы |

Главная обязана отдавать ссылку каждой из 16 страниц кластера: 3 хаба, 12 городов, блог.

## Сборка

```
python3 tools/build.py            собрать сайт в site/
python3 tools/build.py --check    только проверить данные
```

```
data/site.json       бренд, реквизиты, регион, гарантия — общее на весь сайт
data/cities.json     города с падежами, телефонами и районами
data/services.json   контент по услугам: поломки, прайс, марки, FAQ, отзывы
        │
        ▼
templates/*.template.html   токены {{…}} + участки <!-- BUILD:x -->
        │
        ▼
site/<услуга>/index.html
site/_preview/<услуга>.html   копия с относительным путём к assets,
                              чтобы открывалась двойным кликом
```

Шаблон остаётся обычным HTML: его можно открыть в браузере и увидеть пример
со всей вёрсткой. Генератор трогает только 18 содержательных блоков между
маркерами `BUILD`, а шапка, подвал, формы и разметка остаются на месте.

Комментарии-инструкции из шаблонов в собранные страницы не попадают —
они для вас, а не для посетителя, и весят десятки килобайт.

### Что проверяется перед сборкой

Любая ошибка останавливает сборку — лучше не собрать, чем выложить битую
связку город-услуга:

- все города услуги описаны в `cities.json`
- минимум в прайсе совпадает с `price_from` (иначе заголовок «от N ₽» врёт)
- город каждого отзыва входит в список городов этой услуги
- после сборки не осталось незамещённых токенов

## Матрица город × услуга

Списки городов **разные** — следите за битыми ссылками.

| Услуга | Сургут | Нижневартовск | Нефтеюганск | Ханты-Мансийск | Нягань |
|---|:--:|:--:|:--:|:--:|:--:|
| `remont-stiralnyh-mashin` | ✓ | ✓ | ✓ | — | ✓ |
| `remont-holodilnikov` | ✓ | ✓ | ✓ | ✓ | — |
| `kompyuternaya-pomosch` | ✓ | ✓ | ✓ | ✓ | — |

Места, где список зашит:

- **город** — переключатель в topbar, блок «Услуга в других городах», подвал
- **хаб** — переключатель в topbar, секция `#cities`, три `<select>` в формах,
  JSON-LD (`areaServed` + `ItemList`), ссылки под прайсом, подвал
- **главная** — списки городов в карточках офферов, секция `#cities`,
  объект `SERVICE_CITIES` в `/assets/app.js`, JSON-LD `areaServed`, подвал

Матрица не прямоугольная: в Нягани только стиральные машины, в Ханты-Мансийске
их нет. Не дописывайте ссылки «для симметрии» — это 404.

## Что обязано различаться на каждой из 12 страниц

Иначе Яндекс склеит их как малоценные дубли.

1. Районы и посёлки выезда (`#local`)
2. Абзац про специфику города (`#local`)
3. Карта зоны выезда (`#local`)
4. 6 отзывов — имена, районы, модели техники (`#reviews`)
5. Цены — разводить хотя бы на ±10% (`#prices`)
6. 2 городских вопроса (`#faq`)
7. Статьи блога — строго по теме услуги (`#articles`)

## Кольцо перелинковки

```
городская ──→ статья ──→ хаб + все города услуги
    ↑                            │
    └────────────────────────────┘
```

Городская страница ссылается на статьи из блока «Когда пора вызывать мастера»,
хаб — из таблицы симптомов, статья возвращает ссылки на хаб и на все города
своей услуги (блок `#post-cities` и боковая колонка). Без обратных ссылок
статья собирает трафик и никуда его не отдаёт.

## /spasibo/

Все формы сайта редиректят сюда через `_next`. Три правила:

1. Цель в Метрике: «Посещение страниц», условие — URL содержит `/spasibo/`.
   Это основная конверсия сайта.
2. **Не** закрывать страницу в `robots.txt`. Иначе робот не прочитает
   `noindex` и страница всё равно попадёт в выдачу, только без описания.
3. Исключить из `sitemap.xml`. Формы на страницу не ставить.

## /send.php — обработчик форм

```
server/send.php            обработчик: CSV + почта + Telegram
server/config.sample.php   настройки, скопировать в config.php
server/.htaccess           закрывает config.php и logs/ (Apache)
server/nginx.conf.sample   то же для nginx
```

Все 14 форм сайта отправляются на `/send.php`. Formspree убран: он держит
серверы в США, что расходится с ч. 5 ст. 18 152-ФЗ — запись и хранение ПДн
россиян должны производиться на серверах в РФ.

### Порядок действий, заявка не теряется

```
1. запись в logs/leads.csv   ← единственный критичный шаг
2. письмо
3. Telegram
4. редирект на /spasibo/
```

Диск первым и по делу: почта может залипнуть в очереди, Telegram может быть
недоступен — заявка всё равно лежит в CSV. Обратный порядок (сначала письмо) —
самый частый способ терять заявки молча.

### Установка

1. `cp server/config.sample.php config.php`, заполнить
2. Положить `config.php` выше корня сайта и поправить `CONFIG_PATH` в send.php.
   Если хостинг не позволяет — оставить рядом, но **обязательно** положить
   `.htaccess`, иначе `https://сайт/logs/leads.csv` откроется у кого угодно
3. Создать `logs/` с правами на запись
4. Проверить: `curl -I https://сайт/config.php` и `.../logs/leads.csv` → 403

### Что ещё нужно сделать по 152-ФЗ

- Хостинг должен быть **в России** — иначе раздел 8 политики врёт, там
  написано, что трансграничной передачи нет
- Подать уведомление в РКН об обработке ПДн: смена обработчика от этого
  не освобождает
- Завести cron на чистку `leads.csv` — сроки хранения в разделе 9 политики
  сами себя не соблюдут

### Известные грабли

- **Письма в спам.** `mail()` шлёт через sendmail хостинга. `from_email`
  обязательно на своём домене, в DNS нужны SPF и DKIM. Если не помогает —
  PHPMailer через SMTP, место для подмены помечено в коде.
- **Telegram не доходит.** Часть российских хостеров не пускает запросы
  к `api.telegram.org`. В `logs/error.log` будет ошибка соединения. На запись
  в CSV и на письмо это не влияет.

## /assets/

```
assets/style.css   все стили сайта      56 КБ  (11.5 КБ gzip)
assets/app.js      весь скрипт сайта    16 КБ  ( 4.9 КБ gzip)
```

Один файл на все 16 страниц: браузер скачивает их один раз и переиспользует
дальше. Разбиение по типам страниц дробило бы кэш ради экономии пары килобайт.

### Класс типа страницы на `<body>`

```html
<body class="page-city"
      data-phone="{{PHONE_E164}}"
      data-metrika="{{METRIKA_ID}}"
      data-modal-fallback="#lead-form">
```

Класс нужен там, где разным типам страниц требуется **разное поведение одного
селектора** — при объединении файлов такие правила перетирали бы друг друга.
Все такие случаи собраны в секции «Переопределения по типам страниц» в конце
`style.css`. Новый тип страницы — заводите класс и дописывайте туда, а не
правьте общие правила.

Классы: `page-home`, `page-hub`, `page-city`, `page-post`, `page-blog`,
`page-thanks`, `page-policy`, `page-404`.

### Конфигурация через data-атрибуты

Внешний JS один на все страницы, поэтому подставлять в него токены нельзя —
телефон может отличаться по городам. Значения приходят из `<body>`:
`data-phone` (запасной сценарий модалки), `data-metrika` (номер счётчика),
`data-modal-fallback` (куда прокрутить, если браузер не знает `<dialog>`).

### Цели Метрики больше не закомментированы

Раньше код целей лежал закомментированным в каждом шаблоне — восемь мест,
где легко забыть. Теперь цели отправляются всегда, а функция `goal()` молча
выходит, если счётчика нет или `data-metrika` пуст. Завести в Метрике:
`call`, `form_send`, `service_click`, `city_click`, `blog_to_city`, `page_404`
(тип «JavaScript-событие»). Главная конверсия — по-прежнему цель на URL
`/spasibo/`, а не на submit формы.

### Превью

`examples/` содержит копию `assets/` и ссылается на неё относительным путём,
чтобы страницы открывались с диска. В шаблонах путь абсолютный — `/assets/…`,
иначе на вложенных URL и на 404 ссылки сломаются.

Комментарии-подсказки в шаблонах уезжают в продакшен как есть. Если захотите
их вырезать — это делается одним проходом минификатора на выкладке, трогать
исходники не нужно.

## Правило синхронизации

Тексты FAQ продублированы в JSON-LD `FAQPage` в `<head>`. Правите вопрос
на странице — правьте и разметку, иначе это несоответствие разметки контенту.
То же с ценами: `{{PRICE_FROM}}` должен совпадать с минимумом в прайсе,
а `hasOfferCatalog` — с таблицей цен.
